# web: obslam bench dashboard

Internal bench tool for the RPLIDAR S2M1 on the servo-tilted cradle. Talks to the core server (`docs/api.md`, section 3) over REST and a WebSocket.

```
bun install        # once
bun run mock       # fake core on http://127.0.0.1:8000 (no hardware needed)
bun run dev        # Vite on http://127.0.0.1:5173, proxies /api and /ws to :8000 (or CORE_URL=http://127.0.0.1:8001)
bun run build      # production bundle in web/dist (the core serves it in prod)
```

Also: `bun run typecheck` (both tsconfigs) and `bun run check` (headless REST + WS contract check against whatever is on :8000; against the real core it moves the servo and runs a short sweep).

## Panels

The first tab, **Operator**, is for the person at the deployment point rather than the bench, and is the default. It hides the sidebar and shows three numbers (Seen = coverage %, Possible voids, Next = the next-station suggestion as "1.3 m toward 206°" or "rotate scanner 90°"), one map and a "What we have" column. The map (top-down canvas, scanner marker, 1 m grid, drag to pan, wheel to zoom, Fit) has a single rendering of the kind-4 layers from `GET /api/ops/layers`: green = can walk (lighter where marginal), red = blocked, one hatch for everything not seen yet (shadow, blind and unknown alike); only voids (V1…) are outlined and labelled, plus the next-station arrow. Hover says x, y and "can walk" / "blocked" / "not seen". "What we have" is the situation report from `POST /api/ai/sitrep`, fetched after every analysis (a core without a key answers with a template; when a model wrote it the block says "assistant summary" with the cost), and an Ask box (`POST /api/ai/ask`, plain-text answer, a route answer is drawn on the map); without a decisions model it says "Assistant off: no API key". The action bar has Scan (the Scan job form in the store; "scanning… step 12 of 61" inline), Route (click start then goal; "4.2 m, passable" or "no passable route: …"; the button then clears) and Report (map PNG + findings JSON). Analysis never refreshes while a sweep is running (a partial sweep gives a nonsense floor fit): it refreshes on mount, on Refresh, and when a kind-3 grid frame arrives with no job running or the job stops after one arrived (sweep end, session load); meanwhile the previous analysis stays, the map says "scanning… 12/61" and the three numbers go grey. `findings.scan` from newer cores is used when present. If the lidar or servo is not connected and no session is loaded, the map area says so.

**Advanced ▸** (remembered in localStorage) opens everything else under the action bar: layer toggles (terrain ramp, traversability, shadow and blind hatches, findings, next station), cell size and max-step parameters (both re-query), Refresh analysis, Fit, Stop sweep, the full situation block (coverage, area seen, floor reach, shadow / blind / unknown cells with their notes, floor fit, scanner height, traversability counts, limits, next-station reason), route details, the four finding lists (click to highlight and pan), and the assistant ranking (`POST /api/ai/triage`, sorted by attention with a confidence bar and the reason). With Advanced open the map also outlines and labels obstacles, depressions and shadows, and the hover readout shows the height and the class name.

The left sidebar holds the controls: **Connection** (port list from `/api/ports` with refresh, source `s2` or `sim`, baud, connect/disconnect, and the device info from the status object: model, serial, firmware, health, scan Hz, points per rev, range; the servo has the same with a `sim` entry), **Servo** (slider in servo degrees within the reported limits, numeric tilt φ, home, and a raw console for `?`, `C ...`, `L ...` calibration lines showing the reply), and **Scan job** (name, φ start/end/step, rotations, settle ms, start/stop, progress bar, step x of n, points, ETA, state). The other tabs are the engineering views. **Live scan** draws the latest kind-1 frame on a canvas polar plot (range rings, angle ticks, native clockwise angle, points coloured by quality) next to big numbers (scan Hz, points, min/max range) and a virtualised raw table with an angle filter. **Point cloud and height map** is a react-three-fiber scene that accumulates kind-2 frames into a preallocated 2M-point buffer coloured by z (orbit, grid at z=0, axes, reticle at the tilt axis, clear button, optional surface mesh from the grid) beside the top-down 2.5D height map from kind-3 frames (NaN transparent, hover shows x/y/z, cell size, layer and z range controls that PUT `/api/config` and GET `/api/grid`). **Sessions** lists `/api/sessions` with load, grid, PLY/CSV export and delete. **Log** shows the last 200 log messages; the status bar at the bottom shows the WebSocket state with auto-reconnect and a one-line summary of lidar, servo, job and cloud size.

## Layout of the code

- `src/api/types.ts`, `src/api/frames.ts`: the contract types and the little-endian binary codec (shared with the mock and the check script).
- `src/api/ws.ts`: WebSocket client with exponential backoff; parses frames off the render path and throttles scan pushes to 10 Hz.
- `src/store/store.ts`: zustand store. `src/store/cloud.ts`: the point buffer, kept outside React; the 3D view uploads only the new slice each frame.
- `src/components/*`: one file per panel. `src/styles.css`: the only stylesheet (dark, neutral grey, one accent).
- `src/store/ops.ts`: state for the Operator tab (parameters, findings, layers, situation report, route, selection, Advanced flag) and the sweep-aware refresh. `src/store/actions.ts`: sweep start/stop shared by the job panel and the operator action bar. `src/components/Ops*.tsx`: the tab (`OpsTab`), the map (`OpsMap`), "What we have" (`OpsSummary`), the Advanced panel (`OpsAdvanced`) and its pieces (`OpsFindings`, `OpsAssistant`).
- `mock/server.ts`, `mock/world.ts`: Bun mock of the core with a fake room that is ray-cast at the current tilt. `mock/ops.ts`: a port of the core's `analysis.py` (floor fit, classes, obstacles, voids, shadows, blind stripe, A* route) over the mock cloud, plus canned `/api/ai/*` answers built from the findings. `MOCK_AI=off bun run mock` behaves like a core without an API key (status unavailable, template sitrep, 503 on ask and triage).
- `scripts/check.ts`: headless contract check, including the kind-4 codec round trip, `/api/ops/*` and `/api/ai/*`.

Tabs are deep-linkable: `#ops`, `#live`, `#cloud`, `#sessions`, `#log`.
